# 扫描版中英文 PDF 转带页码 Markdown 实测指南（v2.0 · Mac & Windows 双端实测版）

面向搭建 **LLM-Wiki（Obsidian + Agent）** 的研究者，遇到内嵌文字层为 `0` 字符的**纯图片/扫描版 PDF 书籍或论文**时，第一步的核心诉求只有五件事：
1. **默认保留精确双页码**（`PDF p.X | 原书 p.Y`），通过全书众数自动推算印刷页码差值并识别罗马数字前言，杜绝把印刷装订记号（`A/B/P/Q`）或 OCR 误识（`12I`、`III`）当成页码；
2. **默认纯本地免费模型转换**（`MinerU 4.2` `basic` ONNX 引擎，文档识别本身耗费 **`0` 元 API 费、`0` 大模型 Token**）；
3. **默认在 Agent 对话里一句话触发**（通过 `scanned-pdf-to-markdown` Skill 自动调度，无需去终端手敲长串命令）；
4. **默认写入 Obsidian 的 `brain/raw/books/` 并加 `0444` 只读锁 + 每 25 页断点自动续传**（防止中断重跑，也防止下游便宜大模型误改原文）；
5. **默认先 1 秒预估耗时**：短任务（`≤ 60 秒`）直接转换；长书先报预估分钟数与本机负载提示，获准后后台运行、支持 `status` 查实时剩余时间，并在完成时触发系统桌面通知。

> **数据标注原则**：本文所有性能与成本数字均严格区分 **【实测】**（附带当时的机器空闲内存与系统负载条件）与 **【推算】**，绝不把切片外推数字冒充整书实测。

## 一、为什么上游 `MinerU` 原项目外还需要包一层薄 Skill（`v2.0`）？

核查上游 `opendatalab/MinerU` 官方仓库及其自带的 `skills/mineru/SKILL.md` 后，实测对比如下：

| 痛点维度 | 上游 `MinerU` 原版 CLI / 官方 Skill | 本仓库 `scanned-pdf-to-markdown` Skill (`v2.0`) |
|---|---|---|
| **页码保留与纠错** | `mineru-kit parse -o book.md` 默认**删光全部页码**（【实测】`has_page_markers: false`）；若直接信单页 OCR 页码，古籍装订字母 `B/P/Q` 与 `121→12I` 会产生每本十余页错标 | 全书众数自动推算 `PDF页码 - 原书页码` 固定差值（并识别罗马数字前言与书末附页），单页 OCR 仅作交叉核对，【实测】自动拦截修正 Toynbee 全书 `15` 处页码误识 |
| **表格与插图/统计图分流** | `middle_json` 对 PDF 默认剥离 `image_base64`（见 `mineru/parser/base.py`），直接渲染会丢弃插图；而开启重型 `advanced` VLM 转述图表易幻觉且极慢（见官方 Issue `#5708` / `#5728`） | **表格（`table`）**直接转结构化 Markdown / HTML `<table>`；**插图与数据图（`image` / `chart`）**版面隔离不扫乱码，按 `bbox` 自动从原 PDF 裁出 200 DPI 高清 `.png` 存入 `raw/books/assets/<书名>/` 并内嵌 `![](assets/...)` 链接 |
| **耗时预估与高负载感知** | 无预估，前台阻塞数十分钟 | `estimate` 自动读取本机历史实测中位数（`rates.jsonl`）并检测系统 `load average`；运行中可调 `status` 查看按已完成分块计算的实时剩余时间 |
| **完成通知与只读保护** | 无系统通知；生成文件可被模型随意改写 | 内置 macOS `osascript` / Windows 托盘气泡系统级完成通知；生成 `.md` 自动加 `0444` 只读保护锁 |
| **断点续传与防爆内存** | 中断需重跑；手动多开易打爆虚拟内存 | 每 25 页原子落盘缓存（【实测】20 页缓存重跑仅 `1.26 秒`）；按平台空闲物理内存动态限制并发进程数 |
| **为什么选 Skill 不选 MCP** | — | 整本 500 页专著转换需数十分钟，MCP 单次工具调用必超时，且常驻进程浪费内存；`Skill + 单文件标准库脚本` 仅占约百余 Token 描述开销，全客户端通用 |

## 二、MacBook Pro (M5 Pro) vs Windows 轻薄本 (i7-1260P) 真机实测数据

测试真书样本（均为内嵌文字层 `0` 字符的纯扫描 PDF）：
- **中文扫描专著**：20 世纪社会学经典合集（**545 页**，`38.6 MB`，`1000×1447` 约 72 PPI 灰度扫描，含脚注与形近词）
- **英文扫描古籍**：1884 年版英国工业革命讲义（**390 页**，`43.0 MB`，`3300×5175` 600 DPI CCITT 二值传真扫描，含无框线人口统计表、罗马数字前言、双栏小字注文与印刷装订字母）

### 1. 双平台真机实测总表（严格附负载与内存条件）

| 测试项目 | MacBook Pro（Apple M5 Pro · 15核 · 48GB） | Windows 轻薄本（Intel i7-1260P · 12核16线程 · 16GB · Iris Xe） |
|---|---|---|
| **推理运行时** | `ONNX Runtime` ARM64 CPU（`basic` 档） | `onnxruntime-directml 1.24.4`（`basic` 档，免装 PyTorch） |
| **隔离目录从零首装总耗时** | Python 包约 `25s` + 模型缓存 `805 MB`（首次） | **【实测】`141.3 秒`（`2.36 分钟`）**（含 `venv 559 MB` + `ONNX 模型 818 MB` 全量下载；空闲内存 `5.38 GB`） |
| **545 页中文整书全量耗时** | • 轻负载 5 进程：**【实测】`50 分钟`（`5.5 秒/页`）**<br/>• 重度拥塞时不建议整书硬跑（见下栏） | **【实测】`46.97 分钟`（`2818.1 秒`，`5.17 秒/页`）**（`workers=2`，空闲内存 `5.09–7.60 GB`，初始 CPU `1%`） |
| **390 页英文整书全量耗时** | • 轻负载 5 进程：**【实测】`51 分钟`（`7.9 秒/页`）** | **【实测】`30.28 分钟`（`1817.0 秒`，`4.66 秒/页`）**（`workers=2`，空闲内存 `7.60–7.66 GB`） |
| **20 页切片速度（正常轻负载）** | 单进程：**【实测】中文 `6.17 秒/页`（`2.06m`）· 英文 `7.66 秒/页`（`2.55m`）** | 双进程：**【实测】中文 `5.80 秒/页`（`1.93m`）**<br/>单进程：**【实测】中文 `11.49 秒/页` · 英文 `11.88 秒/页`** |
| **20 页切片速度（极端高负载反例）** | 当后台常驻百余进程、`load 188–999`、`Swap 14–26 GB`、空闲内存 `<1.3 GB` 时：<br/>**【实测】`w1=88.0s/页` · `w2=61.5s/页` · `w4=32.9s/页`**（慢 5–14 倍！） | — |
| **断点续传耗时（20页已缓存）** | **【实测】`< 1.0 秒`**（`0` 页重算） | **【实测】`1.26 秒`**（`0` 页重算） |
| **文档识别本身 API 费用** | **`0 元` / `0 Token`** | **`0 元` / `0 Token`** |

> **关键经验**：为什么上表中 16GB 的 Windows 轻薄本跑整书（`47 分钟`）甚至追平了 48GB 的 M5 Pro（`50 分钟`）？一是 Windows 版 `onnxruntime-directml` 极轻巧（双进程仅占约 `1.6 GB` 内存）；二是实测证明**一旦机器发生严重 Swap 交换内存拥塞，本地 OCR 速度会暴跌 5–14 倍**——这正是 `pdf2md.py v2.0` 同时监控空闲内存与 `load average` 预警的原因。

### 2. 原图核验错字率与 935 页跨平台一致性（【实测】）

- **原图逐字核对错字率**：
  - 中文低清扫描件（抽样 7 页正文/注文共 `3,994` 字）：`MinerU 4.2 ONNX` 仅 `3` 处形近误识（`自已`×2、`讣闻→认闻`×1），**实测错字率 `0.75‰`（每千字 `0.75` 字，优于同批 macOS Vision 的 `2.50‰`）**，且完整分离页眉与页脚注文。
  - 1884 年英文扫描件（抽样 6 页共 `11,113` 字母数字）：正文错字率 **`< 0.6‰`**，无框线人口表成功转为 `<table>` 结构（仅极浅断墨数字在跨平台间偶有差异）。
- **Mac 与 Windows 935 页全书逐页比对**：
  - 不同硬件指令集（ARM64 CPU vs x64 DirectML）浮点舍入存在极微小差异，并非 100% 逐字节相同：
  - **545 页中文全书**：字均相似度 **`99.97%`**（去标点后 `509/545` 页完全一致）；
  - **390 页英文全书**：字均相似度 **`99.80%`**（去标点后 `283/390` 页完全一致），差异主要在目录省略号点数、弯直引号及个别断墨表格数字。

## 三、便宜模型（`DeepSeek-V4.1-Flash`）vs 强模型（`DeepSeek-V4-Pro`）真实四场景实测

为检验低价模型在真实工具调用循环（无任何预设参数提示、无预先授权）中能否可靠驱动本 Skill，我们使用官方 API 对 **`deepseek-flash`**（低价模型）与 **`deepseek-v4-pro`**（强模型对照）进行了 **4 大场景共 17 轮真机实测**：

1. **场景 S1（短篇扫描件直接转）**：`deepseek-flash` **`3/3` 全过**，`deepseek-v4-pro` **`1/1` 通过**；四次独立运行产出的 Markdown 正文与参考基准 **100% 逐字完全一致**——实证表明：**只要参数封装进确定性脚本且输出加 `0444` 只读锁，调度模型的贵贱对转换正文质量的影响严格为 `0%`**。
2. **场景 S2（545页整书必须先报预估时间等授权）**：`deepseek-flash` **`3/3` 全过**，`deepseek-v4-pro` **`1/1` 通过**——均准确调用 `estimate` 报出 `545` 页、预估分钟数与 `0 元` 成本，并在未获授权前严格停手不跑 `convert`。
3. **场景 S3（25页已缓存 + 1页未转的中断续传）**：`deepseek-v4-pro` **`1/1` 4 步干脆通过**；`deepseek-flash` 初测 **`2/3` 通过**（失败的 1 次是因为便宜模型自己好奇去翻查缓存目录耗尽了轮次上限；在 `SKILL.md` 增加“禁止翻查内部目录”红线后复测 **5 步一次通过**）。
4. **场景 S4（未装环境的冷启动拦截与首装）**：冷启动首检拦截 `deepseek-flash` **`3/3` 全过**（均如实报告需先运行 `setup` 而未谎报成功）；首次全量安装排错在修掉 `uv venv --clear` 与本地轮子复用后复测一次跑通。
5. **真实花费（官方账单实扣）**：跑满全部 **17 轮试验（含 4 轮 Pro 强模型）总计仅扣费 `0.46 元人民币`**——平时用 `deepseek-flash` 调度转换一本书，Agent 侧 API 成本仅约 **`0.01–0.02 元`（1 到 2 分钱）**。

## 五、使用方法（一句话全自动）

### 1. 挂载 Skill（仅需一次）
- **macOS / Linux**：
  ```bash
  mkdir -p ~/.agents/skills ~/.claude/skills ~/.gemini/skills
  ln -sfn ~/Documents/brain/skills/scanned-pdf-to-markdown ~/.agents/skills/scanned-pdf-to-markdown
  ln -sfn ~/Documents/brain/skills/scanned-pdf-to-markdown ~/.claude/skills/scanned-pdf-to-markdown
  ln -sfn ~/Documents/brain/skills/scanned-pdf-to-markdown ~/.gemini/skills/scanned-pdf-to-markdown
  ```
- **Windows（PowerShell）**：
  ```powershell
  New-Item -ItemType Directory -Force -Path "$HOME\.agents\skills", "$HOME\.claude\skills" | Out-Null
  Copy-Item -Recurse -Force "$HOME\Documents\brain\skills\scanned-pdf-to-markdown" "$HOME\.agents\skills\"
  Copy-Item -Recurse -Force "$HOME\Documents\brain\skills\scanned-pdf-to-markdown" "$HOME\.claude\skills\"
  ```

### 2. 日常在 Agent 中一句话调用
直接在对话框里对 Agent 说：
> `把 "/绝对路径/某某扫描书.pdf" 转成带页码的 Markdown 放进 brain/raw/books/`

输出格式示例（位于 `~/Documents/brain/raw/books/某某扫描书.md`，自动设为只读保护）：
```markdown
<!-- pdf_page: 37 | book_page: 25 | ocr_page: 25 | header: 差序格局 -->
### [PDF p.37 | 原书 p.25 · 差序格局]

我们的格局不是一捆一捆扎清楚的柴，而是好像把一块石头丢在水面上所发生的一圈圈推出去的波纹。每个人都是他社会影响所推出去的圈子的中心。
```
