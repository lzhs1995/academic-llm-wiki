# 扫描版中英文 PDF 转带页码 Markdown 实测指南（Skill v2.2 · Mac & Windows 双端实测版）

面向搭建 **LLM-Wiki（Obsidian + Agent）** 的研究者，遇到内嵌文字层为 `0` 字符的**纯图片/扫描版 PDF 书籍或论文**时，第一步的核心诉求只有五件事：
1. **默认保留精确双页码**（`PDF p.X | 原书 p.Y`），按连续页共同的「PDF 页码 − 印刷页码」差值分段推算（罗马数字前言、正文、书末另起页码的附页、从 p.231 开始的节选、书中插图页造成的跳号都能分开），单页识别出的页码只用来投票和核对，所以印刷装订记号（`A/B/P/Q`）或 OCR 误识（`12I`、`III`）不会变成页码；每页标明页码是印着读到的还是推算的；
2. **默认纯本地免费模型转换**（`MinerU 4.2` `basic` ONNX 引擎，文档识别本身耗费 **`0` 元 API 费、`0` 大模型 Token**）；
3. **默认在 Agent 对话里一句话触发**（通过 `scanned-pdf-to-markdown` Skill 自动调度，无需去终端手敲长串命令）；
4. **默认写入 Obsidian 的 `brain/raw/books/` 并加 `0444` 只读锁 + 每 25 页断点自动续传**（防止中断重跑，也防止下游便宜大模型误改原文）；
5. **默认先 1 秒预估耗时**：短任务（`≤ 60 秒`）直接转换；长书先报预估分钟数与本机负载提示，获准后后台运行、支持 `status` 查实时剩余时间，并在完成时触发系统桌面通知。

> **数据标注原则**：本文所有性能与成本数字均严格区分 **【实测】**（附带当时的机器空闲内存与系统负载条件）与 **【推算】**，绝不把切片外推数字冒充整书实测。

## 一、为什么上游 `MinerU` 原项目外还需要包一层薄 Skill（`v2.2`）？

核查上游 `opendatalab/MinerU` 官方仓库及其自带的 `skills/mineru/SKILL.md` 后，实测对比如下：

| 痛点维度 | 上游 `MinerU` 原版 CLI / 官方 Skill | 本仓库 `scanned-pdf-to-markdown` Skill (`v2.2`) |
|---|---|---|
| **页码保留与纠错** | `mineru-kit parse -o book.md` 默认**删光全部页码**（【实测】`has_page_markers: false`）；若直接信单页 OCR 页码，古籍装订字母 `B/P/Q` 与 `121→12I` 会产生每本十余页错标 | 按连续页的 `PDF页码 - 原书页码` 差值分段推算（罗马数字前言、正文、书末附页、节选、插图跳号），单页 OCR 只作投票与核对；【实测】Toynbee 全书 `17` 页、费孝通 `1` 页 OCR 读出的页码字样与实际不符（装订字母 `A/B/P/Q/R/T`、`12I`、`III`、章首页读成 `1`），都按前后页改正 |
| **表格与插图/统计图分流** | `middle_json` 对 PDF 默认剥离 `image_base64`（见 `mineru/parser/base.py`），直接渲染会丢弃插图；而开启重型 `advanced` VLM 转述图表易幻觉且极慢（见官方 Issue `#5708` / `#5728`） | **表格（`table`）**直接转结构化 Markdown / HTML `<table>`；**插图与数据图（`image` / `chart`）**版面隔离不扫乱码，按 `bbox` 自动从原 PDF 裁出 200 DPI 高清 `.png` 存入 `raw/books/assets/<书名>/` 并内嵌 `![](assets/...)` 链接 |
| **耗时预估与高负载感知** | 无预估，前台阻塞数十分钟 | `estimate` 自动读取本机历史实测中位数（`rates.jsonl`）并检测系统 `load average`；运行中可调 `status` 查看按已完成分块计算的实时剩余时间 |
| **完成通知与只读保护** | 无系统通知；生成文件可被模型随意改写 | 内置 macOS `osascript` / Windows 托盘气泡系统级完成通知；生成 `.md` 自动加 `0444` 只读保护锁 |
| **断点续传与防爆内存** | 中断需重跑；手动多开易打爆虚拟内存 | 每 25 页原子落盘缓存（【实测】20 页缓存重跑仅 `1.26 秒`）；按平台空闲物理内存动态限制并发进程数 |
| **为什么选 Skill 不选 MCP** | — | 整本 500 页专著转换需数十分钟，MCP 单次工具调用必超时，且常驻进程浪费内存；`Skill + 单文件标准库脚本` 仅占约百余 Token 描述开销，全客户端通用 |

## 二、MacBook Pro (M5 Pro) vs Windows 轻薄本 (i7-1260P) 真机实测数据

测试真书样本（均为内嵌文字层 `0` 字符的纯扫描 PDF）：
- **中文扫描专著**：20 世纪社会学经典合集（**545 页**，`38.6 MB`，`1000×1447` 约 72 PPI 灰度扫描，含脚注与形近词）
- **英文扫描古籍**：1884 年版英国工业革命讲义（**390 页**，`43.0 MB`，`3300×5175` 600 DPI CCITT 二值传真扫描，含无框线人口统计表、罗马数字前言、双栏小字注文与印刷装订字母）

### 2. 原图核验错字率与 935 页跨平台一致性（【实测】）

- **错字抽查（两套引擎对照，是下限，不是逐字校对）**：方法是把 MinerU 与另一套引擎的结果逐字对齐，只在两者不一致处看原图判定谁错；两者错得一样的字查不出来。
  - 中文（7 页、`3,994` 字，对照 macOS Vision）：MinerU 错 `3` 处（`自己→自已`×2、`讣闻→认闻`×1），约 `0.75‰`；Vision 错 `10` 处，约 `2.5‰`。`自已` 两处已对原图确认原书印的是「自己」。
  - 英文（6 页、`11,113` 个字母数字，对照 Tesseract 5）：两者共有 `26` 处小差异，多数是脚注序号和页码有无，判定后 MinerU 的正文错字少于 `0.6‰`。
- **页码核对（原图）**：两本书共看了 `32` 页原图（前言、正文起始、章首、书末附页、易错页）。其中印有页码的 `18` 页：`14` 页标签与印刷页码一致，`4` 页是费孝通书前言的罗马页码（i、iii、iv、vii）识别不出、标为「未标页码」；没有一页标错数字。没印页码的 `14` 页：标为「未标页码」，或带 `basis: extrapolated / inferred` 标明是推算。
- **Mac 与 Windows 整书逐页比对（同版本脚本、同分块，11-19 两边各跑一遍）**：不是逐字节相同。
  - 545 页中文：`534` 页完全相同，去掉标点空白后 `542` 页相同，字符相似度 `99.999%`；
  - 390 页英文：`314` 页完全相同，去掉标点空白后 `362` 页相同，字符相似度 `99.994%`；相似度最低的几页在书末出版社广告目录（PDF p.370–380）。

## 三、便宜模型（`deepseek-flash`）vs 强模型（`deepseek-v4-pro`）真实工具循环实测

11-19 11:00–11:45（台北时间）用 DeepSeek 官方 API 让模型自己调用 shell 工具驱动本 Skill（v2.0），提示词里不给参数、不预先授权。每个场景 `deepseek-flash` 跑 3 次、`deepseek-v4-pro` 跑 1 次，另加 1 次 flash 从零安装。共 17 次：**flash `11/13` 通过，pro `4/4` 通过**（pro 每场景只有 1 次，样本很小）。

1. **S1 短篇直接转**：flash `3/3`、pro `1/1`。4 次输出的正文与基准逐字相同——转换由脚本完成，调度模型强弱不改变转出来的文字。
2. **S2 545 页整书先报时**：flash `3/3`、pro `1/1`，都先调用 `estimate` 报页数、分钟数和 0 元，没授权前没有启动 `convert`。
3. **S3 中断续传**：pro `1/1`；flash `2/3`。失败的那次 flash 一直去翻缓存目录，用完轮次也没转完，**还把测试缓存复制进了用户真实书库 `~/Documents/brain/.vault-meta/ocr-cache/`**（测试脚本没有隔离 HOME；11-20 已清理）。`SKILL.md` 加「不要翻缓存目录」后单次复测通过。
4. **S4 未装环境**：flash `3/3`、pro `1/1` 都如实报告要先 `setup`。flash 从零完整安装那次（S4b）跑了 `1,481` 秒、13 次调用，没走到 `convert`，判失败；修掉 `uv venv --clear` 问题后单次复测通过（复测时 uv 已有本地缓存，不是冷下载）。
5. **花费**：17 次共用 flash 输入 `244,952` token（其中缓存命中 `209,920`）、输出 `21,406`；pro 输入 `31,163`（命中 `22,656`）、输出 `4,667`。按 DeepSeek 官网价目（测试时段属高峰价）、1 美元 = 7.1 元折算，约 **`0.48` 元**。测试脚本前后读的余额（0 → 9.53 元）不可信，所以这不是账单实扣数。flash 转一篇短文的调度费约 `0.02` 元。

结论：便宜模型能按 4 步完成常见流程，但会越界乱翻、甚至写到别处，所以 v2.1 起由脚本自己把关：拒绝覆盖不是它生成的文件、拒绝同一本书并发、输出只读。

## 五、使用方法（一句话全自动）

### 1. 挂载 Skill（仅需一次）
- **macOS / Linux**：
  ```bash
  mkdir -p ~/.agents/skills ~/.claude/skills ~/.gemini/skills
  ln -sfn ~/Documents/brain/skills/scanned-pdf-to-markdown ~/.agents/skills/scanned-pdf-to-markdown
  ln -sfn ~/Documents/brain/skills/scanned-pdf-to-markdown ~/.claude/skills/scanned-pdf-to-markdown
  ln -sfn ~/Documents/brain/skills/scanned-pdf-to-markdown ~/.gemini/skills/scanned-pdf-to-markdown
  ```
- **Windows（PowerShell）**：
  ```powershell
  New-Item -ItemType Directory -Force -Path "$HOME\.agents\skills", "$HOME\.claude\skills" | Out-Null
  Copy-Item -Recurse -Force "$HOME\Documents\brain\skills\scanned-pdf-to-markdown" "$HOME\.agents\skills\"
  Copy-Item -Recurse -Force "$HOME\Documents\brain\skills\scanned-pdf-to-markdown" "$HOME\.claude\skills\"
  ```

### 2. 日常在 Agent 中一句话调用
直接在对话框里对 Agent 说：
> `把 "/绝对路径/某某扫描书.pdf" 转成带页码的 Markdown 放进 brain/raw/books/`

长书时 Agent 先报预估分钟数，你确认后它在后台转：Claude Code 用后台 Bash，跑完自动通知 Agent；其他客户端用 `convert --background`，跑完弹系统通知，期间可让 Agent 跑 `status` 报进度。

输出格式示例（位于 `~/Documents/brain/raw/books/某某扫描书.md`，自动设为只读保护）：
```markdown
<!-- pdf_page: 37 | book_page: 25 | basis: printed | ocr_page: 25 | header: 差序格局 -->
### [PDF p.37 | 原书 p.25 · 差序格局]

我们的格局不是一捆一捆扎清楚的柴，而是好像把一块石头丢在水面上所发生的一圈圈推出去的波纹。每个人都是他社会影响所推出去的圈子的中心。
```
`basis` 说明页码来源：`printed` 本页印着且读对；`corrected` 本页读出的数字不对、已按前后页改正；`inferred` 本页没印页码但夹在有页码的页之间；`extrapolated` 本页没印页码、在一段页码头尾外推（标题会写「无印刷页码，推算」，引用前看原图）。
